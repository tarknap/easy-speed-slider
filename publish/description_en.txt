Why I made it

I got tired of tracking a pile of interdependent settings by hand — especially when you change filament all the time. So I made a small workaround that at least makes life a bit easier.

Part of this logic already exists in OrcaSlicer, but not for every line type.

The idea is that for good print quality the speeds of different line types should not differ too much from each other. Taking it further: to keep a balance between quality and speed, it makes sense to set a dependency between line speeds using the outer wall speed as the base. The outer wall defines how the finished part looks, and when tuning a print people lean on it first.

That is why this mini-plugin exists: in its settings you can enter an averaged dependency of line speeds on the base outer perimeter speed, based on your own experience and tests.

Easy Speed Slider — one slider for your print speeds.

The short slider sets the outer wall speed. Every other speed in the table takes either a multiplier of it (×2 = twice as fast as the wall) or its own speed in mm/s — those rows do not follow the slider. Each row has a "why" note, saved separately for every preset.

"Apply" writes everything into the current preset in one commit — the preset becomes modified, so save it. "Reset to base" restores the original proportions of the profile. Travel, first layer and filament settings are left untouched.

If the printer settings define a resonance-avoidance (VFA) speed band, the plugin warns when the outer wall speed falls inside it; with resonance avoidance enabled it also shows the speed the slicer will actually print the wall at.

If the filament has a maximum volumetric speed, the plugin estimates the speed limit from line width and layer height and highlights the rows the slicer will cap.

Bilingual interface (RU/EN). Requires OrcaSlicer 2.5.0 or newer. On first load OrcaSlicer asks for permission to create a worker thread — without it the plugin cannot edit presets.
